The Explain App — Documentation

What the app is, how to use the player and editor, and how to serve lessons from GitHub, Google Docs, or any URL.

What is the Explain app?

The Explain app is a lecture player that turns a simple text file into an interactive, narrated lesson. You write content using markdown and special blocks, and the app shows text, speaks it aloud, runs code, shows diagrams, and asks questions.

Block types (quick reference)

Lesson content is made of blocks. Each block starts with ::: (three colons) followed by a block name, optionally with arguments in parentheses. The block body is everything after that until the next line that starts with :::. For narrated content, write_speak is the usual default (show and speak).

Example:

::: write_speak
This text is shown and spoken.

::: wait(click=true)

::: write
This line is shown only (no speech).

::: r 
plot(1:10) # This line adds code and a plot to the presentation

#The next line adds a multiple choice question
::: question
What is the meaning of life?
- 41
* 42
- 42

::: python
print("Hello, world!")

All block types (use each with a ::: prefix, e.g. ::: write):

  • Text: write, write_speak, speak
  • Pacing & structure: wait, new_page, title, defaults
  • Callouts & interactivity: message, question, multiple_choice, mark, mark_image, annotate_image, annotate_table
  • Media & embedding: image, img, table, math, html, video, youtube, pdf, link, accordion
  • Web components: webcomponent (define), web (use)
  • Code: pyodide, webr, js
  • Diagrams & drawing: draw, new_drawing, mermaid, p5, svg
  • Other: dim, no_dim, xplainer_link

Next we describe the player and editor, then block types in detail, and finally inline tags and other options.

Player features

When you're watching a lesson, the bottom bar gives you full playback control.

Playback: Play and Pause, Rewind, Previous page, Next page. A progress bar and time display show where you are in the lesson.

Speed: Choose 0.75×, 1×, 1.25×, 1.5×, or 2× for speech and pacing.

Accessibility: CC for captions, Mute for turning off speech. Fullscreen for a distraction-free view.

Edit: The pencil button opens the built-in editor so you can change the script or try your own content.

The editor — what it does

The editor is where you write and load lesson scripts. Open it with the Edit (pencil) button in the bottom bar.

Editor actions

  • Play — Load the current text into the player and start from the beginning.
  • Close — Hide the editor and return to the player.
  • Help — Toggle a short reference for block syntax and common commands.
  • Download — Save the current script as a .txt file to your computer.
  • Save as app — Export a single HTML file that runs the app (scripts loaded from CDN). Great for offline or custom hosting.

The editor — loading content

You can get content into the editor in several ways.

Load from URL: Paste a URL or a short identifier in the “URL or id…” field and click Load. The app fetches the file and puts it in the editor. You can then play it or edit it.

Tutorial list: Use the dropdown next to Load to pick from a list of built-in or configured tutorials. Click the refresh button to reload the list.

Upload: Click Upload to choose a .txt, .md, or .json file from your computer. The content appears in the editor and you can play or edit it.

::: webcomponent

Define a custom element (web component) so you can use it later with ::: web. The tag name must contain a hyphen (e.g. my-card). Definitions run when the lecture loads, before any ::: web block.

Two ways to define:

  • Import by script: ::: webcomponent my-chart(script="https://example.com/my-chart.js") — load the script; it must call customElements.define('my-chart', ...).
  • Inline code: Body = JavaScript or Brython that registers the element. Use lang=js (default) or lang=brython.

Example (Brython):

::: webcomponent note-card(lang=brython)
from browser import webcomponent, html

class NoteCard:
    def __init__(self):
        self.attachShadow({'mode': 'open'})
        self.shadow <= html.DIV(Class='note-card') <= (
            html.DIV(Class='note-title', id='title'),
            html.DIV(Class='note-body', id='body'),
        )
    def connectedCallback(self):
        self.shadow.select('#title')[0].text = self.attrs.get('title') or ''
        self.shadow.select('#body')[0].innerHTML = self.attrs.get('content') or ''
webcomponent.define('note-card', NoteCard)

Keywords and defaults:

script
URL of a script that defines the custom element. If set, body is ignored.
lang
Language for inline body: js (default) or brython.
shadow
Whether the component uses shadow DOM. Default: true.
body_attr
When set, block body is sent to this attribute by default (so you can write ::: comp TAG without into=). Default: content.

::: comp / ::: component

Create an instance of a web component (custom element) that was defined with ::: webcomponent or by a loaded script. Syntax: ::: comp TAG_NAME(key=value, ...) or ::: component TAG_NAME(...). Optional body.

Body behavior:

  • If you include into="attrname" (or into= for the default), the block body is set on that attribute and is not appended as children.
  • If you do not use into and the component was defined with body_attr, the block body is sent to that attribute.
  • Otherwise the block body is appended as DOM children (e.g. for the default slot).

Examples:

::: comp note-card(title="First", into="content")
This is the body — passed into the content attribute.
::: comp note-card(title="Second")
  <p>This paragraph is appended as a child (slot).</p>

Keywords:

tag
Set by parser from header: ::: comp TAG_NAME(...).
into
Reserved: attribute name that receives the block body. Use into="attrname" or into= (default content).
location
Column: "left" | "right".
speak
Optional phrase to speak.
Any other key=value
Set as attributes on the custom element.

Inline tags in write/speak: (( )) and ((!))

Inside write_speak (and in the spoken part of other text blocks), you can use double parentheses to control what is shown vs. spoken, change language or voice for a phrase, or apply fonts and styles. All of these features use the (( )) syntax; ((!name!)) is a special form for the next word only.

Show / speak only: ((silent)), ((invisible)), ((skip))

Wrapped content can be write only, speak only, or neither:

  • ((silent))...((/silent)) or ((s))...((/s)) — shown on the board only, not spoken.
  • ((invisible))...((/invisible)) or ((i))...((/i)) — spoken only, not shown.
  • ((skip))...((/skip)) or ((k))...((/k)) — neither shown nor spoken.

Example: See ((silent)) Figure 3 ((/silent)) for details. — “Figure 3” appears on screen but is not read aloud.

Stop writing or speaking: ((stop_write)), ((stop_speak))

Single tokens (no closing tag):

  • ((stop_write)) — from this point on, nothing more is shown on the board for this block (speech continues).
  • ((stop_speak)) — from this point on, nothing more is spoken (text continues to appear).

Change language, voice, or rate: ((say))...((/say))

Use ((say key=value))...((/say)) to override speech options for the wrapped phrase. Supported arguments:

  • speech_lang or lang — e.g. lang="en-GB", lang="nb-NO".
  • speech_voice or voice — voice name or male/female.
  • speech_rate or rate — number (e.g. 0.8 for slower, 1.2 for faster).

Example: ((say lang="en-GB" rate=0.9))This sentence uses British English and a slower rate.((/say))

Apply a style preset (fonts, colors, voice): ((use name))...((/use))

((use presetName))...((/use)) applies a named preset to the wrapped content. Presets are defined in ::: defaults under speech_tags, inline_presets, or styles. They can set:

  • Text style: color, background, font_family / font, font_size / size, font_weight / weight, font_style, text_decoration.
  • Speech: speech_lang / lang, speech_voice / voice, speech_rate / rate.

Example: define a preset in defaults with a different font and colour, then ((use emphasis))...((/use)) to apply it to a phrase.

Style the next word only: ((!name!))

((!presetName!)) applies a named preset to the next word only (no closing tag). Same preset options as ((use)) (fonts, colors, language, voice, rate). Example: The key term is ((!highlight!)) important here. — the word “important” gets the preset named highlight.

Serving your app via URL hash

You don't have to use the editor every time. You can open a specific lesson directly by adding a hash to the app URL. The app supports three prefixes.

GitHub: Use #github- followed by either a full GitHub file URL or a path like owner/repo/branch/path/to/file.txt. The app loads the raw file from GitHub.

xplainer.app/#github-username/repo/main/lessons/intro.txt

Google Docs: Use #gdoc- followed by the document ID or the full Google Docs sharing URL. The app exports the doc as plain text and loads it. The document must be shared so that “Anyone with the link” can view.

xplainer.app/#gdoc-17ljz_ftXbM-tsPOe0vnNpQRp52gCEntapeXvc3KW9bw

Serving — any URL

Any URL: Use #url- followed by the full URL of a text or markdown file. The app fetches that URL and loads the content. Best for plain text or markdown; HTML pages may need the target to be set up for export as text.

xplainer.app/#url-https://example.com/lecture.txt

So you can host lessons on GitHub, write them in Google Docs, or put them on any server — and share a single link that opens the app with that lesson already loaded.

Summary

The Explain app is a lecture player that turns text scripts into narrated, interactive lessons. Use the player to watch and control playback; use the editor to write, load, download, and save scripts. Serve lessons by sharing links with #github-, #gdoc-, or #url- so the app loads your content automatically.

Recap
  • Player: play/pause, progress, speed, fullscreen, captions, mute, edit.
  • Editor: Play, Close, Help, Download, Save as app; Load from URL, list, Upload.
  • Serving: #github-path-or-url, #gdoc-doc-id-or-url, #url-any-https-url.
